I'm not claiming a mapping to the models we heard today: the point is that it exists, and people struggle to read it.

an analogy · 05Mendeleev, 1869–1871 · simplified: groups I–VII, first five rows

A periodic table, published as a list of elements.

About sixty elements were known, each with its weight and its chemistry.

As a list ordered by weight, they are just numbers.

Arranged by weight and by behaviour, the same data leave holes.

Titanium behaves like silicon: it moves right, and a gap opens. Arsenic behaves like phosphorus: two more gaps.

1871: Mendeleev describes the missing elements, weights included.

Found: gallium 1875, scandium 1879, germanium 1886.

Gallium's discoverer measured a density of 4.7. Mendeleev, who had never seen the element, wrote that it should be about 6. Purified and remeasured: 5.9.

The arrangement added no data. It made the gaps visible, and a gap can be tested.

Weights as in Mendeleev's 1871 table; group VIII omitted. Gallium: Lecoq de Boisbaudran (1875); scandium: Nilson (1879); germanium: Winkler (1886). Weights of the discovered elements are today's values.
[0:50] A better-known case. Around 1869 Mendeleev worked with the elements already known, each with its weight and chemistry. As a list ordered by weight, they are just numbers. [→] Arranged by weight and by behaviour, they leave holes. Titanium behaves like silicon, so it moves right and a gap opens under aluminium; arsenic behaves like phosphorus: two more gaps. In 1871 he described the missing elements, with their weights. [→] Gallium was found in 1875, scandium in 1879, germanium in 1886. And the best part: gallium's discoverer measured a density of 4.7; Mendeleev, who had never seen the element, wrote that it should be about six. Purified and remeasured: 5.9. Ontologies aren't chemistry, and I won't predict a single class. But the lesson holds: the arrangement added no data. It made the gaps visible, and a gap is something you can test.

how it works · 10paper, Sect. 5

Merge first, then compute the closures.

CIDOC CRME4 E7 E31 E54 … P70 …
CRMsciS2 S5 S13 S21 S27 … O5 O24 …
CRMdigD9 D11 … L20 …
CRMinfI1 I2 … J2 …
→
one dictionary, keyed by bare code
E7 S5 D11 I1 S21 E4 I2 D9 …
then the closures, over the union
S5 ⊑ I1 ⊑ E7 ⊑ E5 ⊑ E4
D11 ⊑ S21 ⊑ S27 ⊑ I1
S13 ⊑ S11 ⊑ S10 ⊑ S15 ⊑ E1
no namespace logic

A chain crosses a model boundary the way it crosses any other edge.

a bounded search

Bidirectional, subsumption at every hop; up to 4 steps, 600 states per level, 100 results. Truncation is shown.

“loose”

The ends fit the declared domain or range only through a distant superclass: flagged, and hideable.

[0:35] How it works, in one sentence: every loaded model is merged into one dictionary keyed by bare code, and only then are the closures computed. [→] So S5 inherits from I1, D11 from S21, and the search contains no namespace logic at all: a chain crosses a model boundary the way it crosses any other edge. The path finder is a bounded bidirectional search; when it truncates it says so, and chains whose ends only fit through a distant superclass are flagged “loose”.

scope · 13paper, Sect. 5 · what is verified and what is not

What it does, and what it doesn't.

verified

Entity counts against the official declarations, recomputed by a script shipped with the paper.

verified

The transitive subclass closure across model boundaries.

documented, not scripted

The path results: each one is a deep link you can re-enter.

absent by design

subPropertyOf entailment: a real limit, since CRMsci alone declares 40 subproperty links.

absent by design

owl:inverseOf (inverses exist because the RDFS lists them), transitivity, cardinality, quantifiers, shortcuts.

no consistency checking

It prevents an inadmissible triple; it does not diagnose one.

“No path found” is not a proof of absence. An admissible triple says what the schema allows, not that the model is adequate.

Where it sits: LODE 2, presented this morning, aggregates modules into documentation to read; an editor with a reasoner builds and verifies an ontology. This tool is for applying a standard you did not design. Full comparison in the bonus tracks.
[0:40] Let me be precise about what this is. Verified: the counts, against the declarations, with a script shipped with the paper; and the subclass closure across models. The demos are deep links: re-enterable, documented, not scripted. [→] Absent by design: subproperty entailment, a real limit since CRMsci alone declares 40; owl:inverseOf, transitivity, cardinality, shortcuts; no consistency checking. [→] So “no path found” is not a proof of absence, and an admissible triple tells you what the schema allows, not that a claim is true or a model adequate. bonus · CRMsci · 4paper, Sect. 4 · App. figure

Adding CRMsci: four small things, and nothing else.

what it took

A registry entry, two code-prefix declarations, a data file and a provenance hue.

a hue chosen by measurement

Indigo #3A3FA0: 37° of hue from its nearest neighbour among the model and family colours, 8.8:1 contrast on white.

coloured on arrival

20 of 28 classes took their family colour from the hierarchy; grey marks classes under no anchor. Note I1 above S5 and S27.

The same four steps, plus a wider code pattern for two-letter prefixes (SP, AP), would bring in CRMgeo, CRMarchaeo or CRMba.
bonus · editors · 5paper, Sect. 3

Why not an ontology editor with a reasoner? Same power, different purpose.

raw capability

Load the four RDFS files into an editor with an OWL reasoner and the capability is there: an upper bound.

building and verifying

An editor's unit of work is the axiom; its question is whether a model is consistent.

applying

The common task is downstream: translating “this sample was measured, and here is the file the instrument wrote” into codes of a standard you did not design.

the cost of the question

“Which properties may hold between a sample and a data object?” There: a reasoning environment and a formal query. Here: ?path=S13,D9.

Documentation and modelling support are usually separate artefacts; for a modular standard they should not be.
